- `require('@dynamic-solutions-canada/web-app-kit')` and `require('@dynamic-solutions-canada/web-app-kit/eslint')` now resolve instead of failing with `ERR_PACKAGE_PATH_NOT_EXPORTED`, so tests that load components through `require()` can reach the kit. On Node 22.12 and later, `require()` and `import` return the same module.
- Under tsx (the `devkit-test` loader), a `require()`d kit is compiled to a second copy with its own dialog stack. Keep each test file on one route, all `require()` or all `import`; the README's "ES modules only, require() too" entry explains.
- In an npm workspaces monorepo, a root `eslint.config.mjs` can fail to import the kit's lint config when the kit is installed only under one workspace. Declare it at the root too, or import the config from inside that workspace; see the README's lint section.
